# 04 · AI辅助与个人贡献

## 如实记录

本仓库由候选人与AI助手协作创建。不能将AI生成或AI执行的内容表述为候选人独立完成。以下仅记录本次会话中已经发生、可以核实的工作。

| 工作 | 已确认承担者与范围 |
| --- | --- |
| 提供完整试题、允许AI辅助的规则 | 候选人 |
| 选题建议、实现范围与架构建议 | AI助手提出，候选人确认第二题 |
| 指定模型、接口、提供本机系统变量与GitHub仓库 | 候选人 |
| 代码、合成数据、测试、评估脚本、初版文档 | AI助手在本地工作区编写 |
| 执行测试、真实模型调用、检查Trace、修正边界问题 | AI助手通过工具实际执行，证据见examples |
| 业务Agent运行时的工具选择与重规划 | 真实模式由deepseek-flash完成；离线模式为明确标注的规则Mock |
| 候选人手工改代码、独立复现与理解核验 | 尚未在会话中发生，不宣称完成 |

AI编程助手与业务Agent中的模型是不同角色：前者辅助构建项目，后者是在项目运行时根据工具观察选择动作。真实模型仍使用合成业务工具；没有把本地脚本模板说成真实文案模型服务。

## AI使用范围

AI辅助涵盖需求拆解、Python原生循环、工具参数规范、预算/时间校验、SQLite状态与幂等、CLI、Mock、测试用例、真实评估和文档整理。未使用额外子Agent，未引入Agent框架。

工程验证包括实际pytest运行、离线9场景、真实DeepSeek9场景，以及逐步Trace核对。已修正的问题包括小数边界被四舍五入放行的风险、跨评估时钟复用旧报价的风险。测试事实与结果详见03文档，不能将这些工具执行记录冒称人工测试。

## 候选人后续记录方式

提交前建议本人实际复现离线与真实命令，阅读预算调整与故障恢复Trace，亲自选择一处改进并说明原因。发生后在本节追加日期、具体文件/commit、修改动机、验证命令及实际结果；在完成前保留“尚未独立复核”的事实。

密钥由操作系统环境变量提供，没有在仓库、示例输入或文档中保存真实凭证；API错误只记录类别和状态码。所有业务资料为合成，没有使用真实客户隐私数据。
