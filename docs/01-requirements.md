# 01 · 需求与成功标准

## 用户与问题

目标用户是运营人员：给定活动主题、预算和截止时间，希望得到可执行的内容方案，知道费用是否可承受、步骤是否真正完成、失败后还能复用哪些结果。

选择第二题。核心范围为 CLI 输入 → 模型选择工具 → 本地业务执行 → 模型观察并调整 → 保存合成方案或明确停止。检索、脚本生成、估算、保存均有可调用工具。

## 输入与交付

输入包含 request_id、theme、budget、deadline，可选 preferences。主题、预算、截止时间缺失时不猜测。预算允许小数但不能为负、布尔值、NaN 或无穷；截止时间必须带时区。request_id 只允许字母、数字、下划线及连字符，最长64位。

输出包含步骤状态、素材与脚本、候选估算、最终费用、保存位置/状态、缺失字段和未完成原因。Trace 包含每次模型选择的动作、参数、公开的一句话依据、工具返回及后续动作。任务状态为 completed、needs_input 或 incomplete；输入或存储等入口错误为 error。

任务计划中的 completed 仅指已完成合成资料选择、模板脚本生成和本地保存，不表示真实制作、投放或活动落地。

## 成功标准

| 验收项 | 预期 |
| --- | --- |
| 正常完成 | 合法估算后生成脚本与保存，费用和时间通过检查 |
| 缺预算或截止时间 | needs_input，列出缺失字段，零模型/业务调用 |
| 工具失败 | 不将失败步骤标成功；保留成功产物，允许重试或停止 |
| 预算超限 | 模型看到费用后改选并重新估算，或明确未完成及缺口 |
| 重复执行 | 同一请求只保存一份方案；已完成请求不再调用模型 |
| 失败续跑（加分） | 同一请求恢复后不重新生成已有成功脚本 |
| 决策边界 | 至少两条真实模型路径体现观察结果后的不同动作 |
| 循环上限 | 模型轮数/工具次数均有限，触顶返回未完成 |
| 时间约束 | 不晚于截止时间；不满足时可调整或停止 |

## 范围与非目标

使用合成素材、模拟费用与预计串行耗时，实际保存到 SQLite。不包含前端、线上部署、真实采购、并行生产调度或真实发布。单进程原型优先支持可解释的核心链路与可复现验证。
